Insecure Direct Object Reference

User-controlled IDs used to access resources without authorization checks allow users to access others data.

#SeverityFindingFileLineCode
1HIGHDirect object referencegetvouch/fix_prompts.py313f" const resource = await db.findById(params.id)\n"
AI Fix Prompt
SECURITY FIX NEEDED — Insecure Direct Object Reference (IDOR) at getvouch/fix_prompts.py line 313
Issue: A resource is fetched using a user-controlled ID with no check that
the requesting user is authorized to access it.
Code: f"  const resource = await db.findById(params.id)\n"

Fix getvouch/fix_prompts.py line 313 — add an ownership check after fetching:

  // Fetch the resource
  const resource = await db.findById(params.id)

  // Check existence
  if (!resource) return res.status(404).json({ error: 'Not found' })

  // Check ownership (use 403 not 404 — 404 leaks that the resource exists)
  if (resource.userId !== session.user.id) {
    return res.status(403).json({ error: 'Forbidden' })
  }

  return res.json(resource)

Search the codebase for every endpoint that accepts an ID parameter and
returns data — each one needs this ownership or permission check:
  /api/users/[id], /api/posts/[id], /api/orders/[id], /api/files/[id]

Verify: sign in as User A, copy the ID of User B's resource, try to access
it as User A — the response must be 403 Forbidden, not the resource data.
